Continuous Deployment with AWS Lambda & GitHub Actions

Why copy-pasting code into the cloud console is an anti-pattern & how to fix it with automated pipelines.

1. The Problem: Manual Console Uploads

In early prototype phases, pasting code into the AWS Lambda web editor is fast. But as applications evolve, manual uploads create three severe problems:

  • Drift: The code running in production no longer matches git history.
  • Lack of Testing: A syntax error or failed unit test immediately breaks live users.
  • Credential Risk: Developers share static admin API keys to push changes.

2. The Solution: OpenID Connect (OIDC)

Instead of hardcoding long-lived AWS_SECRET_ACCESS_KEY tokens in GitHub Secrets (which can leak or expire), GitHub Actions exchanges a short-lived cryptographic JWT directly with AWS IAM via OIDC:

GitHub Actions Runner ---> (JWT) ---> AWS Security Token Service (STS) ---> Temporary 15m Credentials ---> Lambda Deploy
