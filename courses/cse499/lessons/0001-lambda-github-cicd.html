Lesson 0001: Connecting AWS Lambda to GitHub Actions

Eliminate manual console copy-pasting by using GitHub as the single source of truth for your AWS Lambda code.

1. The Problem: Manual Console Drift

Right now, your Lambda function code is updated manually in the AWS Console. This creates several risks:

  • Drift: What is running in the cloud may not match what is in git history.
  • Friction: Every fix requires packaging, logging into the console, and uploading.
  • Lack of Tests: Untested changes can break the preview endpoint immediately.

2. Architecture: How GitHub Deploys to Lambda

[git push / merge to branch]
      │
      ▼
[GitHub Actions Workflow]
      ├─ 1. Run Tests (vitest & tsc --noEmit)
      ├─ 2. Assume AWS IAM Role (OIDC - No hardcoded secrets!)
      ├─ 3. Zip Lambda code (lambda/index.mjs)
      └─ 4. Run: aws lambda update-function-code --function-name <NAME> --zip-file ...
      │
      ▼
[AWS Lambda (Live Preview Endpoint)]

3. The 3 Steps to Wire It

  1. Consolidate the Code: Keep the Lambda file tracked in lambda/index.mjs in this repo.
  2. Configure AWS OIDC IAM Role: Give GitHub Actions permission to run lambda:UpdateFunctionCode without permanent AWS access keys.
  3. Add a Workflow: Create .github/workflows/deploy-lambda.yml that triggers on changes to the lambda directory.
