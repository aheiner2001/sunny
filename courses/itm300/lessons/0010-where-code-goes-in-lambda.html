Where Does the Code Go in the Lambda File?

Understanding why it goes inside export async function handler(event) instead of the very top of the file.

Top of the File vs. Top of the Handler

In JavaScript/Node.js, there is an important difference:

  • The very top of the file (Line 1): This runs only once when AWS boots up your Lambda container (called "cold start"). Here you put import statements and client initializations.
  • The start of the handler(event) function (Line 3442): This runs every single time someone knocks on the door! Every time a manager clicks preview or a cron fires, AWS passes the event to this function.

The Exact Two Spots in lamdba/index.mjs

Spot A: Inside the top of handler(event) (around Line 3444)

Here we check: "Did an API Gateway request just arrive?"

  // 2. If it's an API call, read query params like ?week=current

Spot B: Inside the preview return (around Line 3570)

Here we check: "Should we return standard HTTP status code and headers?"

  if (!send) {
    const previewPayload = {
      mode: "preview",
      message: "No email sent.",

      period: report.period,

    // If API Gateway called us, wrap in HTTP response:
    if (isHttpApi) {

          "Content-Type": "application/json",
          "Access-Control-Allow-Origin": "*",
          "Access-Control-Allow-Methods": "GET,OPTIONS"
        },

      };
    }

    // Otherwise return direct object (for direct AWS CLI / test console)

Why This Structure is So Clean

Notice that you do not have to touch or rewrite the thousands of lines in the middle (the date math, Firestore queries, and report tables). The calculation engine stays 100% intact!
