Lesson 0006

How the Production Lambda Works (Without the Confusion)

Demystifying lamdba/index.mjs step-by-step so you can adapt it with confidence.

The 30,000-Foot View

The file in lamdba/index.mjs is 3,600+ lines, but its core job is very straightforward:

  1. Read Cloud Configuration: Grabs credentials from AWS Secrets Manager and checks environment variables (Timezone, Recipient emails).
  2. Fetch Operational Data: Authenticates with Google Cloud/Firestore and pulls 5 collections: vehicles, equipment, inspections, timesheet_shifts, timesheet_corrections.
  3. Compute Analytics: Aggregates shift hours, detects vehicle service gaps, and checks inspection warnings.
  4. Format and Deliver: Formats the numbers into HTML + CSV attachments. If dryRun: true, it returns the summary JSON without emailing. If dryRun: false, it delivers via AWS SES.

The Core Lambda Flow


  [AWS EventBridge / Cron Trigger]
               │
               ▼
  handler(event) in index.mjs
    ├─ 1. Authenticate with Google (getGoogleToken via Secrets Manager)
    ├─ 2. Fetch Firestore collections in parallel (readCollection)
    ├─ 3. Run business rules: buildAnalytics(data, ...)
    ├─ 4. Render email text & HTML: renderReport(analytics)
    └─ 5. Return JSON preview OR send via SES

Key Takeaways for Your Mission

  • Dry-run safety: The handler defaults to or supports { dryRun: true }, which runs all computations without sending emails or modifying databases.
  • Separation of Concerns: Data fetching is decoupled from report generation logic (buildAnalytics and renderReport).
  • Timezone precision: Always operates against Denver boundaries (America/Denver) to ensure consistent weekly shift sums.

Quick Self-Check

Question: When testing the Lambda function locally or via AWS console, what parameter ensures no actual emails get sent to fleet managers?
