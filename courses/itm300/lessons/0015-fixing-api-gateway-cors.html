Why Browsers Block CORS and How to Enable It in API Gateway

Solving Response to preflight request doesn't pass access control check in 60 seconds.

What Just Happened? (The "Preflight" Check)

Your Vercel app is hosted at: https://sunny-3mqxv0rrz-gooly.vercel.app

When a website on Vercel asks a server on AWS for data with a custom header (like Authorization), the web browser sends a silent "security check" first: 


  Browser (Vercel)                    AWS API Gateway
        │                                    │
        │── 1. HTTP OPTIONS (Preflight) ────▶│
        │      "Can Vercel talk to you?"     │
        │                                    │
        │◀─ 2. HTTP 404 (Not Found!) ────────│
        │      "I don't know who OPTIONS is" │
        ▼                                    ▼
  ❌ Browser blocks the real request before it even starts!

The 60-Second Fix in AWS Console

API Gateway has a built-in switch that automatically answers these browser checks. Here is how to turn it on:

  1. In AWS Console, open your API: sunny-fleet-api.
  2. In the left sidebar, click CORS.
  3. Click the Configure button on the right.
  4. Set the following values:
    • Access-Control-Allow-Origin: *
    • Access-Control-Allow-Headers: Authorization,Content-Type,*
    • Access-Control-Allow-Methods: Select GET and OPTIONS
  5. Click Save!

That's it! API Gateway will now immediately reply 200 OK to browser preflight checks from Vercel.

Once you click Save in the AWS console, refresh Vercel and click the button!
