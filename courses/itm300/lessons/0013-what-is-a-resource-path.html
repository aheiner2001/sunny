Lesson 0013

What Is a Resource Path and Where Does It Live?

Demystifying URLs, routes, and why we chose /reports/weekly/preview.

1. Anatomy of a Web Address (URL)

Every web request is broken into two main parts: 

https://abc123xyz.execute-api.us-west-2.amazonaws.com /reports/weekly/preview
└──────────────────────────┬────────────────────────┘ └───────────┬──────────┘
             Domain Name (Base Address)                Resource Path (The Room)
  • Base Domain: Tells the internet which server in AWS to visit.
  • Resource Path: Tells AWS API Gateway which specific action or room to enter inside that server.

2. Where Did /reports/weekly/preview Come From?

It didn't come out of thin air—it is directly defined in your capstone project requirements!

  1. The Project Spec (MISSION.md):
    "Success looks like: Author and test a standalone local HTTP server handling GET /reports/weekly/preview?weekStart=YYYY-MM-DD..."
  2. Your Prototype Server (prototype/server.mjs):
    if (req.method === 'GET' && parsedUrl.pathname === '/reports/weekly/preview')
  3. Your AWS Lambda Prototype (aws-lambda/index.mjs):
    if (path.endsWith('/reports/weekly/preview'))

When you type /reports/weekly/preview into API Gateway's Configure Routes box, you are telling AWS: "Whenever someone visits this exact path, send the request directly to my Lambda function!"

3. Can It Be Named Anything Else?

Yes! You could name it /preview, /report, or /api/weekly.

However, in REST API design, naming paths hierarchically (like folders on a computer) is standard best practice:

  • /reports → We are asking about reports (not employees or vehicles).
  • /reports/weekly → It's the weekly report (not monthly or annual).
  • /reports/weekly/preview → It's a live preview (not sending emails).

Quick Check

Question: Where in the AWS Lambda code can we see the path being read?

Answer: In the event object as event.rawPath! When API Gateway forwards the request, it sets event.rawPath = "/reports/weekly/preview".
