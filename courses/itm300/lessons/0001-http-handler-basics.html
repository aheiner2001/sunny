Building Your First HTTP Report Preview Handler

Welcome to Lesson 1! In this lesson, you will create a standalone, local Node.js HTTP server that handles a GET /reports/weekly/preview?weekStart=YYYY-MM-DD request and returns JSON calculations for manager review.

Why standalone? Sunny Fleet's Next.js application exports statically to HTML/JS. Running a separate Node service lets us develop server-side API endpoints locally without breaking existing static hosting.

1. What Happens in an HTTP Request

When a manager requests a preview via curl or a browser, the raw HTTP transaction consists of three distinct phases:

  1. Request Line & Headers: GET /reports/weekly/preview?weekStart=2026-11-02 HTTP/1.1
  2. Routing & Query Extraction: The server parses the path and inspects the weekStart parameter.
  3. Response Body & Content-Type: The server writes Content-Type: application/json and serializes the summary object.

2. The Reporting Target Math

For the week of Monday, Nov 2, 2026 in America/Denver, our manager report preview needs to reflect:

  • Approved Hours: 1.75 (exactly 1 hour, 45 minutes = 6,300 seconds)
  • Pending Hours: 2.00 (exactly 2 hours, 0 minutes = 7,200 seconds)

3. Interactive Task: Write the Handler

Your Challenge

Create prototype/server.mjs using Node's native node:http module. Follow these requirements:

  1. Listen on port 4000.
  2. Match pathname === '/reports/weekly/preview'.
  3. Extract req.url search param weekStart.
  4. Filter FIXTURE_SHIFTS to only include shifts within that week.
  5. Sum the duration in hours for approved and pending shifts.
  6. Send back a 200 OK response with headers Content-Type: application/json.

4. Verification with curl

Run the server:

node prototype/server.mjs

Execute your curl request in a separate terminal:

curl -i "http://localhost:4000/reports/weekly/preview?weekStart=2026-11-02"

Expected JSON response:

{
  "timezone": "America/Denver",
  "weekStart": "2026-11-02",
  "approvedHours": "1.75",
  "pendingHours": "2.00"
}
